Goal:
In the search service (C13), cache successful search results by normalised query and successful page reads
by final URL for 24 hours, in memory.

Acceptance Criteria (verbatim):
- M20-AC2: "Search service tests: a repeated search (after query normalisation) and a repeated page read (by
  final URL) within 24 hours are served from the Mac-side cache without contacting a backend or the page;
  after 24 hours they are fetched again."

Design decisions already taken (do not reopen):
- Search key: query normalised as trim, lower-case, Unicode NFKC, internal whitespace collapsed to one
  space; plus `max_results`. (A cached entry for a larger max may serve a smaller one by slicing; optional.)
- Read key: the final URL after redirects (`page.finalUrl`). Also remember requested URL -> final URL for
  24 h, so a repeat of the same requested URL is served without contacting the page; a different requested
  URL that redirects to an already-cached final URL is fetched once (to learn the final URL) and may then be
  served from the cached entry — the test must cover the same-URL repeat and the same-final-URL case.
- Only successful responses are cached (search 200 with ≥1 result; read 200). Errors, timeouts, 503s and
  aborts are never cached.
- Entry valid while now < storedAt + 86_400_000 ms; at exactly +24 h it is refetched.
- Bounded: at most 500 search entries and 200 page entries; evict oldest when full.
- A cache hit returns the identical response body and status as the original, plus a response header
  `x-cache: hit` (misses send `x-cache: miss`). No body field changes.
- In memory in the search service process; lost on restart (acceptable).
- Breakers (M20-T2) are consulted only on a cache miss.

Tests required (new file search/src/http/cache.test.ts, existing patterns: fake helper that counts spawns;
loopback test page server via the handler's fetch overrides that counts requests):
1. Search "Heat Pump  costs" then " heat pump costs" within 24 h → helper spawned once; second response
   identical body, `x-cache: hit`.
2. Same search at +24 h → helper spawned again.
3. Read URL U (redirecting to F) twice within 24 h → page server contacted for the first only; at +24 h
   contacted again.
4. Read a different URL that redirects to the same F → served body equals cached F body (page contacted at
   most for the redirect discovery, as designed above).
5. A failing search (503) and a failing read are not cached (second attempt contacts helper/page again).
