built — createServer + GenerationManager + scripted fake Ollama + fake web tools; read both first):
1. Dropped connection: start a deep research run (POST /v1/chat with `web:true, deep_research:true`
   and the configured research model), read the SSE stream of GET /v1/generations/{id}/events only
   up to some event id k (several steps in, before the report), then abort that fetch (the drop).
   Assert the run is still running (e.g. the generation is still active / state reports it), then
   reconnect with header `Last-Event-ID: <k>` and read to the end. The concatenation of the first
   part and the resumed part equals the full log read from scratch afterwards (GET events with no
   Last-Event-ID): same ids in strictly increasing order with no gaps, no duplicate ids, every step
   event's `elapsed_ms`/`budget_ms` identical, exactly one report `content` event, and the terminal
   `done` with `research.status`.
2. Reply in progress: while that run is running, POST /v1/chat with an ordinary message is refused
   with the same status and error code the existing reply-in-progress refusal uses (find it in
   server/src/http/server.ts and webReplyInProgress.test.ts; assert those exact values), and no
   second generation starts.
3. Unload mid-run: while a run is running (the fake search/read/model held open until its signal
   aborts), POST /v1/models/unload without `confirm` is refused with the FR6 confirmation response
   whose reasons include `reply_in_progress` (assert the exact existing shape), and the run keeps
   going; POST again with `confirm: true` → the run's event stream ends with a terminal `done`
   (either `status:"cancelled"` or `research.status:"partial"`) within a bounded time (e.g. 2 s with
   the fakes), the unload completes against the fake Ollama, and the generation slot is released
   (no hang). Use whatever ModelManager wiring / fake Ollama state client the existing unload tests
   in server/src/http/*.test.ts use (grep for "/v1/models/unload" in tests).
