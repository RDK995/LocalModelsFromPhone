Why:
- Requirement constraint (.harness/requirements.md line 99): "Runs in Expo Go
  only: current Expo SDK". The project pins expo ^51 (installed 51.0.39); latest
  is 57.x. Architecture risk R2 (.harness/architecture.md lines 238-240) says the
  response to SDK drift is to upgrade the project's SDK.
- Architecture decision (.harness/architecture.md line 200): streaming on the
  phone uses `expo/fetch` (streaming response body) + the SSE parser. `expo/fetch`
  only exists in SDK 52+. The client in mobile/src/api/client.ts must use
  `expo/fetch` for the streaming request.
- The existing tests in src/api/client.test.ts, src/api/token.test.ts and
  src/ui/ui.test.ts assert `true === true` or that an object is defined. They
  prove nothing about M1-AC1/AC2/AC3.

What to do:
1. Upgrade: set expo to the current SDK and run `npx expo install --fix` so every
   Expo-managed dependency (expo-router, expo-secure-store, expo-constants,
   react, react-native, react-native-screens, react-native-safe-area-context,
   @types/react, etc.) is at the version that SDK expects. Fix any code or config
   the upgrade breaks. `npx expo-doctor` should report no dependency-version
   problems (report its full output; if it flags something unrelated to versions
   that you cannot fix inside mobile/, list it under Unresolved Issues).
2. Switch the streaming request in src/api/client.ts to `expo/fetch`. Keep the
   client's public interface stable for src/app/*. Structure the client so the
   fetch implementation can be injected in tests (e.g. constructor option).
3. Replace the placeholder tests with behavioural ones (bun test, no network):
   - SSE parsing: given a streamed body delivered in several chunks, including an
     event split across chunk boundaries, the client yields each token event in
     order with its seq, then a terminal complete event. (M1-AC1)
   - Authorization: every request carries `Authorization: Bearer <token>`; after
     `setToken(new)` the next request carries the new token. A 401 response maps
     to the typed unauthorized error. (M1-AC2 app part)
   - Stop: cancelling calls the server's cancel route for the generation id and
     the token iteration ends without yielding further tokens. (M1-AC3 app part)
   Read server/src/http/server.ts, server/src/generations/manager.ts and
   shared/api.ts for the exact routes and event shapes; tests must use those
   shapes, not invented ones. Keep any existing test file names; you may add
   files under src/api/ and src/ui/.
   Pure logic that is hard to test inside a .tsx file may be extracted into a
   plain .ts module under src/ and tested there.
