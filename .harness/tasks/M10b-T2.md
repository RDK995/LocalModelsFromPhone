Acceptance Criteria:
1. New file `mobile/src/ui/MarkdownText.tsx` exporting `MarkdownText({ text, style }: { text: string; style?: StyleProp<TextStyle> })`. It calls `parseMarkdown(text)` (wrapped in `useMemo` keyed on `text`) and renders each Block as a `View` stack:
   - paragraph → `<Text style={style}>` with inline children;
   - heading → bold `<Text>` with font size scaled by level (e.g. h1 ≈ base+6, h2 ≈ base+4, h3 ≈ base+2, h4-6 = base, all bold);
   - list → one row per item: a bullet `•` (unordered) or `<n>.` (ordered, from `start`) then the inline text, indented by `depth` (e.g. 12px per level);
   - codeBlock → monospace text (`fontFamily: Platform.select({ ios: "Menlo", default: "monospace" })`) on a light grey background with padding, horizontally scrollable is optional;
   - quote → text with a left border and muted colour;
   - table → one row per table row with cells separated by spacing (no pipe characters), header row bold;
   - rule → a thin horizontal line View.
   Inline: text → string; bold → nested `<Text style={{ fontWeight: "bold" }}>`; italic → `fontStyle: "italic"`; code → nested monospace Text with light grey background; link → nested `<Text>` with the link's children only, NO onPress, NO accessibilityRole="link", no URL shown, same colour as surrounding text.
   Keys must be stable (index-based is fine). Blocks are spaced with a small vertical gap.
2. `mobile/src/app/chat.tsx`: in the message bubble (around lines 401-403), when `item.role === "assistant"` render `<MarkdownText text={item.content} style={styles.messageText} />` instead of the plain `<Text>`; user messages keep the existing plain `<Text style={styles.messageText}>{item.content}</Text>`. The thinking text (around line 353) and everything else (steps, sources list, activity indicator, model label) is unchanged. Streaming replies go through the same path (item.content grows; MarkdownText re-parses).
