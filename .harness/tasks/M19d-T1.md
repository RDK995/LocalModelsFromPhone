TASK M19d-T1 — A deadline-cut note call keeps its complete notes, and a run with no notes because research time ran out says so (FR44 second half, M19d-AC3)

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION — changes the deadline path of
one model step in the research loop plus the failure-sentence choice; clear HTTP-level oracle; no new
concurrency (the parallel-read work is a separate later task, M19d-T2, and is NOT part of this task).

Goal:
1. When the research-phase deadline cuts a "notes" model call part-way through its streamed reply,
   every COMPLETE note object already present in the partial JSON output is kept, after the same FR37
   quote check as a normal note (quote must be a substring of the full stored page text after
   whitespace normalisation; a failing quote is dropped). The run then moves on to writing exactly as
   a deadline does today (researchCutShort, write phase, status `partial` if a report is written).
2. A run that ends with no notes because the research time ran out ends with research status
   `failed` and the report text "The research ran out of time before it could take notes." instead
   of the "could not get anything usable from the pages" sentence.

Required design (keep to it; deviations need a reason in your return):
A. Export a pure function from research.ts, e.g.
   `export function completeNotesFromPartial(partial: string): Array<{ quote: string; claim: string }>`
   that returns every complete object element of the top-level "notes" array found in a possibly
   truncated JSON string, in order, ignoring a trailing incomplete element. It must handle
   braces/brackets and escaped quotes inside JSON strings correctly (track in-string and escape
   state; parse each complete element with JSON.parse). Elements missing a non-empty string quote or
   claim are ignored. Invalid or empty input returns []. No dependency added.
B. Make the partial content available on the deadline path without changing behaviour for any other
   step: e.g. give PhaseTimeUp an optional `partial?: string` field set by sendAttempt to the content
   streamed so far when `name === "notes"`. The PhaseTimeUp must still propagate (never retried) and
   still end the research phase. A hard cancel (signal.aborted, i.e. second Stop / client cancel) is
   unchanged: no salvage. A first Stop (stopSignal) also ends the phase via phaseOver(); salvaging
   complete notes in that case too is acceptable and consistent (FR38 writes a partial report from
   notes so far) — say which you did.
C. Where the notes step is awaited, catch PhaseTimeUp, salvage via completeNotesFromPartial, apply
   the SAME quote check and note push used for a normal reply (refactor into one helper so the two
   paths cannot drift), then rethrow so the run moves to writing.
D. Export `RAN_OUT_OF_TIME_NOTE = "The research ran out of time before it could take notes."`
   Report choice when `failed`: searchesWithResults === 0 -> COULD_NOT_SEARCH_NOTE (unchanged);
   else if the research phase was cut by its deadline (researchCutShort, and not a user Stop — a
   user Stop never reaches `failed`) -> RAN_OUT_OF_TIME_NOTE; else COULD_NOT_READ_NOTE (unchanged).
   Research status stays `failed` in all three. Add a doc comment on the constant.
