TASK M10c1-T1 — Tier: Top (opus). Routing: reason_code SECURITY — extends the SSRF-guarded public-web fetcher (FR21/I18) to a second, binary content path; a mistake here lets the Mac be pointed at local/LAN/tailnet addresses.

Goal:
The search service (C13, `search/`) answers `GET /v1/icon?host=<hostname>` with that website's own icon as image bytes, fetched from the site itself through the same SSRF guard as `POST /v1/read`, cached on disk so a site is fetched once, and `404 {"error":"no_icon"}` when the site has no usable icon. `search/API.md` documents the route.

Relevant Requirements:
- FR27 (.harness/requirements.md lines 130-144): the logo is the site's own icon fetched by the Mac from that website (no third-party logo/favicon service). The Mac's icon fetch applies the FR21 rules (public addresses only, every redirect re-checked, the connected address checked, byte and time limits) and accepts image content only. Logos are cached on the Mac (a site is fetched once, not per request).
- Edge cases (lines 278-281): a site with no icon / that blocks the Mac -> no icon; a local, LAN or tailnet host, or an icon that redirects there -> refused.
- FR25: search/API.md documents every route.
- Architecture deviation D-M10c-2 (.harness/architecture.md, heading `### D-M10c-2`), the C13 bullet, which is the agreed design — follow it exactly:
  `GET /v1/icon?host=<hostname>` -> `200` image bytes | `404 {error:"no_icon"}` | `400 {error:"blocked_destination"|"bad_url"}` | `504 {error:"timeout"}`. It fetches `https://<host>/` through the I18 SSRF-guarded fetcher (same address checks, every redirect re-checked, connected address checked), takes the first `<link rel>` of `apple-touch-icon` / `icon` / `shortcut icon`, else `/favicon.ico`, and fetches that through the same guard. Image content only (`image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/x-icon`, `image/vnd.microsoft.icon`; SVG refused), capped at 256 KiB and 10 s overall. Results — including "no icon" — are cached by C13 on disk under its own cache directory keyed by normalised host (lower-case, leading `www.` stripped), so a site is fetched once; entries expire after 7 days (negative results after 1 day). No third-party favicon service is used.

Acceptance Criteria:

Acceptable shape: an internal lower-level function or options on fetchPage (e.g. allowed types + `binary: true` returning a Buffer); your choice, keep it minimal.
2. New module(s) under `search/src/icon/` implementing: host normalisation; fetch of `https://<host>/` (HTML only), extraction of the first `<link>` whose rel (case-insensitive, token list) is `apple-touch-icon`, `icon` or `shortcut icon`, resolved against the final page URL; if none (or the page fetch fails other than blocked/timeout), `https://<host>/favicon.ico`; the icon itself fetched through the same guard, image types above only (SVG and anything else -> treated as no icon), 256 KiB cap (a larger icon -> no icon, not truncated bytes), 10 s overall deadline across both fetches. If the linked icon fails, falling back to /favicon.ico is fine.
3. Blocked outcomes: a host that resolves to, or whose page/icon redirects to, a non-public address yields `blocked_destination` (the route returns 400 `blocked_destination`, per the design; the server maps this to no_icon later — not your task). An empty/malformed host (scheme, path, port, IP literal, spaces, > 253 chars) -> 400 `bad_url`.
4. Disk cache: directory from env `SEARCH_ICON_CACHE_DIR`, default `~/Library/Caches/harness-search/icons` (create with mode 0700 if missing). One file (or file pair) per normalised host, filename safe (e.g. sha256 of the host). Stores bytes + content type + fetched-at, and negative ("none") entries. Positive entries expire after 7 days, negative after 1 day. Blocked outcomes and timeouts are NOT cached. A cache hit makes no network request (test this with a counting test server). Unreadable/corrupt cache entry -> treated as a miss.
5. Route in `search/src/http/server.ts`: `GET /v1/icon?host=...` (405 for other methods). 200 response has the icon's `content-type` and `cache-control: public, max-age=604800`.
