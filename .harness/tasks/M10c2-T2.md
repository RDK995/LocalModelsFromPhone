Goal:
The phone can ask the Mac for a site's logo: the app server client (C2) gains `siteIcon(host)` calling the Mac's token-protected `GET /v1/icon?host=<host>` and returning a data URI or null, and phone storage (C3) gains an icon cache so a site's logo is not re-asked on every render.

Relevant Requirements:
- FR27 (.harness/requirements.md lines 130-144): the phone never contacts a website or logo service itself — it asks the FR12 server (token-authenticated) for a site's logo. Logos are cached on the phone (not re-asked on every render). When the site has no icon, refuses the Mac, or the Mac is unreachable, a globe icon is shown instead (this task: return null). A logo failing to load never blocks or breaks the answer.
- Architecture D-M10c-2 (.harness/architecture.md `### D-M10c-2`, read the whole section): server route `GET /v1/icon?host=<hostname>` (bearer auth) -> `200` image bytes with the upstream image `Content-Type`, or `404 {error:"no_icon"}`, `400 bad_host`, `502`/`504` `icon_unavailable`. "C2 gains `siteIcon(host) -> dataUri | null` (null on any error; never throws into the UI)." "C3 caches fetched icons on the phone (data URI per normalised host, including a "none" marker) so a render does not re-ask the Mac."

Acceptance Criteria:
- `APIClient.siteIcon(host: string): Promise<string | null>` in mobile/src/api/client.ts: GET `${baseUrl}/v1/icon?host=${encodeURIComponent(host)}` with the bearer header (use the existing `getHeaders()`); on 200 with an `image/*` content type, read `arrayBuffer()` and return `data:<content-type>;base64,<b64>`; any other status, non-image type, thrown fetch error, or abort -> null. Never throws. Base64 encoding must not depend on `Buffer` (not present in React Native); a small local encoder, or `btoa` over a binary string built in chunks, is fine — test it against known bytes. It must only ever request `this.baseUrl` (no other host).
- New `mobile/src/store/iconCache.ts` exporting `createIconCache(storage: StoragePort, fetchIcon: (host: string) => Promise<string | null>)` returning `{ get(host): Promise<string | null>; peek(host): string | null | undefined }`:
  - `peek` returns synchronously what is in memory (data URI, null for "none", undefined if unknown) so a render can show a cached logo immediately.
  - `get` resolves from memory, else from storage key `iconCache:<host>`, else calls `fetchIcon` once; concurrent `get`s for the same host share one in-flight request.
  - A data URI result is persisted to storage and memory. A null result is kept in memory only for the app session ("none" marker) and NOT persisted, so a site whose logo failed because the Mac was briefly unreachable is retried on a later app launch. (Document this choice in a comment.)
  - Storage or fetch errors resolve to null, never throw.

Use `createMemoryStorage` from mobile/src/store/storagePort.ts.
