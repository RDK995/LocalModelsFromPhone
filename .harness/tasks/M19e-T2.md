TASK M19e-T2 — Deep research emits a "started" step before awaiting every search, read and model call (FR45 server started steps, M19e-AC1)

Routing: tier Top, model opus, reason_code DIFFICULT_CONCURRENCY — the research run is an async
generator whose page reads are prefetched in parallel (M19d) under one cancellation signal; a
"started" step for each read must be yielded when the read is initiated, before anything awaits it,
without reordering the one-at-a-time model calls or breaking Stop/deadline draining.

Goal:
In a deep research run, a step event with status "started" (carrying `elapsed_ms` and `budget_ms`
like every deep research step) is yielded — and so reaches GET /v1/generations/{id}/events — BEFORE
the server awaits each:
- web search (today the search's "started" step comes back in the `events` array returned by
  `webTools.search` AFTER it resolves — research.ts ~line 765);
- page read (today `webTools.read(url, ...)` is started at ~line 674 and its "started" step is only
  emitted when its events are drained after it resolves);
- model call other than plan/brief and write (which already yield "plan"/"write" started steps
  before awaiting, lines ~870 and ~992 — keep those): queries -> "Choosing searches", pages ->
  "Choosing pages", notes -> "Taking notes: <domain>" (domain = page hostname without leading
  "www."), gap -> "Checking for gaps". Each later gets a matching "done" or "failed" step with the
  same step_id (failed when the call returned null / was cut).
No duplicate "started" for the same step_id: if the web tool's own events also contain a started
step for a search/read, emit it once (before the await) and drop the late copy. Every other existing
step (done/failed/unavailable for search/read, plan, write) and the sources/content/done events are
unchanged in content and relative order apart from the started steps moving earlier.

Wire shape (interface decision, take as given): extend `StepEventData.kind` in shared/api.ts with
one new member `"model"`; a model-call step is `{ step_id, kind: "model", status, detail: <label> }`
plus elapsed_ms/budget_ms. Also extend the matching `StepEvent` type in server/src/web/tools.ts if it
has its own kind union. Do NOT change mobile/ (the app half is milestone M19f).
