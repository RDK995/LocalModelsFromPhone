TASK M18-T3 — A deep research run shows its phases and clock live, and its finished status, logos and Sources, also when reopened

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION — extends the existing
stream reducer, step labels, persisted message shape and chat rendering for event fields the
server already emits; several app modules but one established pattern.

Goal:
On the phone, a deep research reply shows each phase live as web steps ("Planning",
"Searching: <query>", "Reading: <domain>", "Writing report") plus the elapsed clock against the
budget ("m:ss of 8:00", from the step events' `elapsed_ms`/`budget_ms`); the finished reply shows
its research status (`complete` / `partial` / `failed`), its `[n]` marks as site logos exactly as
ordinary web replies do (FR31), and "Sources (n)" of the pages read; reopening the conversation
from storage shows the same status, steps, logos and Sources.

Relevant Requirements:
- FR34, FR36 (phone shows phases + elapsed vs budget), FR37 (app renders `[n]` as logos and Sources
  is the pages read) — .harness/requirements.md lines 241-285.
- Milestone criterion M18-AC3 (.harness/milestones.md, section "## M18").

What the server already sends for a run (read server/src/generations/research.ts and
shared/api.ts; do not change server/ or shared/):
- `step` events with `kind` in "plan" | "search" | "read" | "write" (plus "continue"/"answer_now"
  for ordinary replies), `status`, `query`/`url`, and on deep research steps `elapsed_ms` and
  `budget_ms`.
- `sources` events whose items carry `n` (FR31 numbering).
- `content` events with the report text containing `[n]` marks (or, for a failed run, a plain
  sentence).
- a terminal `done` event with `status: "complete"` (or "cancelled" on user Stop) and, on a deep
  research run, `research: { status: "complete"|"partial"|"failed"; elapsed_ms; budget_ms }`.

Known gap: mobile/src/ui/chatItems.ts `stepLabel` treats every kind other than search/continue/
answer_now as a read, so "plan" and "write" steps currently render as "Reading".

Acceptance Criteria:
- `stepLabel` labels kind "plan" as "Planning" and kind "write" as "Writing report" (with the
  existing " (failed)" suffix rule for a failed step); search/read labels unchanged.
- A pure formatter, e.g. `researchClockLabel(elapsedMs, budgetMs)` -> "m:ss of m:ss" (e.g.
  192000/480000 -> "3:12 of 8:00"; 0 -> "0:00 of 8:00"; seconds floor; minutes not capped at 59
  is acceptable). The live clock shown for an in-progress run is from the latest step event that
  carries `elapsed_ms`/`budget_ms` (the accumulator tracks it); after `done`, from
  `done.research`.
- mobile/src/ui/streamReducer.ts: the accumulator additionally tracks the latest research clock
  (`{elapsed_ms, budget_ms}`) from step events and the research result from `done.research`
  (status + elapsed + budget). Ordinary replies leave these absent. Tests in streamReducer.test.ts.
- mobile/src/store/conversationStore.ts `Message` gains an optional `research?: { status:
  "complete"|"partial"|"failed"; elapsed_ms: number; budget_ms: number }`; `isValidMessage`
  accepts it (and rejects a malformed one), and still accepts step kinds "plan"/"write" (check
  `isValidStep`). Tests in conversationStore.test.ts that a message with `research` round-trips
  through a fresh store over the same storage port.
- mobile/src/chat/conversationSession.ts persists `research` on the reply when the done event
  carried it (alongside steps and sources with their `n`). Test in conversationSession.test.ts
  with the existing fake client: a scripted deep research stream (plan, search, read, write steps
  with elapsed/budget, sources with n, content with `[1]`/`[2]`, done with research status
  "partial") persists a reply whose content, steps, sources (with n) and `research.status` match;
  a fresh store over the same port returns the same.
- mobile/src/ui/chatItems.ts: `ChatItem` carries `research` (from persisted message, or from the
  pending accumulator's done result) and the live clock for a streaming item; `sources` keep their
  `n` so logos render the same way as ordinary web replies. A pure label for the finished status
  (e.g. `researchStatusLabel("partial")` -> "Deep research: partial") with tests. Tests in
  chatItems.test.ts: a persisted deep research message builds an item with research status,
  steps, sources (with n); a pending streaming item exposes the live clock label.
- Logos: prove with a test that the deep research reply's content and sources go through the same
  citation-to-logo path ordinary web replies use (find it: mobile/src/ui/inlineLink.ts,
  sourceLinks.ts, markdown.ts, SourceLogo.tsx, MarkdownText.tsx) — e.g. the existing pure
  function that turns `[n]` + sources into logo links yields logo links for a deep research item.
  "Sources (n)" uses the existing SourceList / sourceListModel unchanged (assert its label for
  the run's sources).
- mobile/src/app/chat.tsx: for an assistant item with research data, render the clock line
  ("3:12 of 8:00") while streaming and the status label once finished, near the web steps toggle;
  everything else (steps toggle, MarkdownText with logos, SourceList) is the existing rendering.
  Keep logic in pure modules; the .tsx only displays.
