TASK — M6-T1: search/ package scaffold + SSRF-guarded page fetcher (C13 → C15, interface I18)

Routing: Top (opus), reason_code SECURITY — SSRF guard; also resolves architecture risk R6.

Goal:
Create the `search/` Bun package (C13, the loopback search service) and, inside it, a page
fetcher module that fetches an http(s) URL over `node:http` / `node:https` with a custom DNS
`lookup` that refuses any non-public destination at connect time, follows redirects manually with
every hop re-checked, and enforces byte / time / content-type limits. No HTTP server, no HTML
extraction in this task (later tasks).

Relevant Requirements:
- FR21 (.harness/requirements.md lines 93-100): only http/https; refuse any destination that
  resolves to loopback, private (RFC 1918), link-local, CGNAT/tailnet 100.64.0.0/10 (incl.
  100.100.100.100), unspecified, multicast, or IPv6 equivalents (::1, fc00::/7, fe80::/10,
  IPv4-mapped forms such as ::ffff:127.0.0.1); every redirect hop re-checked; the address checked
  is the one connected to (no DNS-rebinding gap); byte and time limits; non-text refused.
- Architecture I18 (.harness/architecture.md lines 276-280): `node:https`/`node:http` with a
  custom `lookup` that resolves EVERY A/AAAA record and rejects if ANY is non-public; the socket
  connects to the checked address. Redirects followed manually, max 5, each re-checked. Caps:
  5 MiB body, 15 s, content types `text/html`, `text/plain`, `application/xhtml+xml` only.
- Architecture risk R6 (lines 364-368): unverified whether Bun's node:http(s) honours a custom
  `lookup`. THIS TASK MUST PROVE IT WITH A TEST. Also reject IP-literal hosts (e.g.
  `http://127.0.0.1`, `http://[::1]`) BEFORE connecting — Node skips `lookup` for IP literals, so
  literals must be checked directly.

Acceptance Criteria (for this task):
- `fetchPage(url, opts?)` (exported from `search/src/fetch/fetchPage.ts`, or similar) returns
  `{ url, finalUrl, status, contentType, body: string }` for an allowed text page, or throws /
  returns a typed error with `code` one of: `bad_url` (unparseable or non-http(s) scheme, e.g.
  `file:///etc/passwd`, `ftp://x`), `blocked_destination`, `unsupported_content`, `fetch_failed`
  (with optional upstream `status`, e.g. non-2xx final response or too many redirects),
  `timeout`. Callers must be able to map `code` to the I16 HTTP responses later.
- An exported pure address classifier (e.g. `isPublicAddress(ip: string): boolean`) with unit
  tests covering at least: 127.0.0.1, 10.x, 172.16.x, 192.168.x, 169.254.x, 100.64.0.1,
  100.100.100.100, 0.0.0.0, 224.0.0.1, 255.255.255.255, ::, ::1, fc00::1, fd12::1, fe80::1,
  ff02::1, ::ffff:127.0.0.1, ::ffff:192.168.1.1 → false; 93.184.216.34, 1.1.1.1,
  2606:4700::1111 → true. Prefer a small hand-written CIDR check or `node:net` BlockList over a
  new dependency.
- The custom lookup resolves all records (`dns.lookup` with `all: true`) and rejects with
  blocked_destination if any record is non-public; otherwise hands the checked address to the
  socket.
- R6 PROOF TEST (required): a test demonstrating that Bun actually uses the custom `lookup` for
  the connection — e.g. a request to a made-up hostname (such as `r6-probe.invalid`) whose
  injected resolver maps it to a local test server's 127.0.0.1 address succeeds ONLY because the
  lookup was used (and the test asserts the lookup was called and the server received the
  request). And a test that a hostname resolving to 127.0.0.1 is refused with
  blocked_destination and the local server receives NO connection. If Bun ignores the custom
  lookup, DO NOT work around it (no pre-resolve-then-fetch-by-IP hack, no Bun fetch, no moving
  work to Python): stop, return BLOCKED, and report exactly what you observed. That outcome is a
  material architecture decision for the human.
- Redirect test: a local server redirecting to a blocked destination is refused with
  blocked_destination (each hop re-checked); more than 5 redirects → fetch_failed.
- Limits test: a body over the byte cap is cut off (either truncated body with a flag, or
  fetch_failed — pick one and document it; the later extraction step truncates the markdown to
  40 000 chars separately, so returning the first 5 MiB with `bodyTruncated: true` is preferred);
  a non-text content type (e.g. `image/png`, `application/pdf`) → unsupported_content; a server
  that never responds → timeout within the configured limit (tests may set a short timeout, e.g.
  300 ms); the fetch accepts an `AbortSignal` and aborts the request when it fires.
- Testability without weakening the guard: tests need loopback test servers, so the fetcher may
  accept an injected resolver and/or address policy via its options, but the DEFAULT (no options)
  must be the strict public-only policy, and IP-literal checks must use the same policy. Document
  in a code comment that production callers must never pass a policy override.
- `cd search && bun test && bun run typecheck` both exit 0.
