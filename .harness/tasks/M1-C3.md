Acceptance Criteria:
- Rules contain ONLY 8081-scoped lines, in this shape (last match wins in pf, so use `quick`):
    pass in quick on lo0 proto tcp from any to any port 8081
    pass in quick on <utunN> proto tcp from any to any port 8081
    block drop in quick proto tcp from any to any port 8081
  No `block all`, no rule without `port 8081`, no `out` rules, no scrub/nat/rdr, no
  table changes. The utun is resolved at install/boot by finding the interface that
  carries the Mac's tailnet IPv4 (`tailscale ip -4`, then `ifconfig`); if it cannot be
  resolved, the script exits non-zero WITHOUT loading anything.
- Loaded under an anchor that the stock macOS /etc/pf.conf evaluates
  (`com.apple/*` wildcard, e.g. `com.apple/harness.bundle-host`) via
  `pfctl -a com.apple/harness.bundle-host -f <file>`; /etc/pf.conf is NOT edited.
  pf must be enabled with a reference (`pfctl -E`) so it does not disable pf for
  others; uninstall flushes only that anchor (`pfctl -a ... -F all`) and releases
  its reference token if recorded — never `pfctl -d`, never `-F all` on the main ruleset.
- A LaunchDaemon plist (/Library/LaunchDaemons/com.harness.pf-bundle-host.plist when
  installed) runs a small loader script at boot (RunAtLoad) that re-resolves the utun
  and reloads the anchor. Install script: ops/scripts/install-pf-anchor.sh;
  uninstall: ops/scripts/uninstall-pf-anchor.sh. Both refuse to run unless root, and
  print exactly what they will do. The human will run `sudo bash ops/scripts/install-pf-anchor.sh`.
- Remove the unsafe ops/scripts/com.harness.pf.anchor and create-pf-anchor.sh (or
  replace them) so nothing in the repo still carries `block all` or tells anyone to
  edit /etc/pf.conf.
- A no-sudo safety check (a bun test or a bash check invoked by verify-ops-install.sh)
  renders the rules for a given utun and asserts: every rule line contains
  `port 8081`; no `block all`; only `in` rules; lo0 and the utun pass rules precede
  the block; the anchor name starts with `com.apple/`. verify-ops-install.sh runs it
  and also checks the LaunchDaemon plist with `plutil -lint`. If `pfctl -n -f` works
  without root on this Mac, also parse-check the rendered rules; if not, say so.
