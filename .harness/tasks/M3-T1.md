TASK M3-T1 — Phone conversation store (C3): create, open, list newest first, delete, update messages; persisted in AsyncStorage and readable by a fresh store after restart

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION
  detail: new persistence module ported from an existing store onto a new storage backend, with a clear unit-test oracle; adds one Expo-Go-bundled dependency.

Goal:
A pure TypeScript conversation store at `mobile/src/store/` that the chat screens (a later task)
will use. It persists every conversation on the phone so that a brand-new store instance built
over the same storage backend (the proxy for "the app was force-quit and reopened") sees exactly
the same conversations and messages.

  Stored in AsyncStorage, one key per conversation plus an index key.

Acceptance Criteria:
- Dependency: add `@react-native-async-storage/async-storage` with `cd mobile && npx expo install @react-native-async-storage/async-storage` (it is bundled in Expo Go; `expo install` picks the SDK-57-compatible version). No other new dependency.
- `mobile/src/store/storagePort.ts`: an async `StoragePort` interface (`getItem`, `setItem`,
  `removeItem`, all Promise-returning), `createMemoryStorage()` for tests, and an AsyncStorage
  adapter. Keep the AsyncStorage import out of any module the bun tests import (e.g. put the
  adapter in its own file such as `mobile/src/store/asyncStorage.ts`), so bun tests never load
  the native module.
- `mobile/src/store/conversationStore.ts`: `createConversationStore(storage, {now?, newId?})`
  returning async methods at least: `list()` (summaries or conversations, sorted by `updated_at`
  descending — newest first), `get(id)` (null when absent), `create(title?)` (new conversation,
  empty messages, persisted), `delete(id)` (removes its key and its index entry),
  `appendMessage(conversationId, message)` and `updateMessage(conversationId, messageId, patch)`
  (both persist and bump `updated_at`), and optionally `rename`/set title. Title defaults to
  something like "New chat" and may be set from the first user prompt (your choice; document it).
  Export the `Conversation` and `Message` types in the shape above.
- Persistence: every mutation is written through to storage before its promise resolves. A second
  `createConversationStore` over the same storage object returns identical conversations and
  messages (ids, roles, content, model, status, order).
- Robustness: a missing or unparseable conversation key referenced by the index is skipped rather
  than crashing `list()`; unparseable index is treated as empty (do not throw into the UI).
- Tests first (Red → Green), `mobile/src/store/conversationStore.test.ts` using memory storage and
  an injected clock: create/get/list newest first (including that appending to an older
  conversation moves it to the top); delete removes it from list and storage; appended assistant
  message keeps its `model`; a fresh store over the same storage sees the same data; corrupt
  entries are skipped. Existing tests must still pass unchanged.
- `bun run smoke:runtime` (bundles the app and runs it) must still pass. The store is not yet
  imported by any screen in this task, so this mainly guards the dependency install.
