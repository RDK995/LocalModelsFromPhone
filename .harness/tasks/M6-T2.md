Goal:
In the `search/` package (C13), add (a) an extractor that turns a fetched HTML/plain-text page
into `{title, markdown, truncated}` using Defuddle over linkedom, truncated to 40 000 characters
with a visible truncation marker; and (b) a Bun.serve HTTP service bound to 127.0.0.1:7790
exposing `POST /v1/read` and `GET /v1/health` exactly per interface I16, using the already-built
guarded fetcher in `search/src/fetch/` (task M6-T1, committed — read it; do not modify its
security behaviour).

Relevant Requirements:
- FR21 (.harness/requirements.md lines 93-100): main content as markdown (boilerplate removed),
  truncated to a fixed size limit and marked as truncated when cut.

  `POST /v1/read` `{url}` → `200 {url, final_url, title, markdown, truncated}`;
  failures `400 {error:"blocked_destination"|"bad_url"}`, `415 {error:"unsupported_content"}`,

Acceptance Criteria (for this task):
- Extractor: given representative HTML with nav/header/footer/sidebar boilerplate and an
  <article> containing a heading, paragraphs and a <pre><code> block, the markdown contains the
  article text and the code block and does not contain the boilerplate strings; `title` is the
  page title. Content over 40 000 chars → `truncated: true`, markdown length bounded (≤ 40 000 +
  marker length) and ends with a clear marker (e.g. `\n\n[… truncated: page exceeded 40000
  characters]`); under the limit → `truncated: false`, no marker. If the fetcher reported its
  body was cut at the byte cap, the result is also `truncated: true` with the marker.
- Service: `search/src/index.ts` (entry, `bun run src/index.ts`) starts Bun.serve with hostname
  hard-coded `127.0.0.1` (not overridable by env) and port 7790 (port may be overridable via env
  `SEARCH_PORT` for tests only). Unknown route → 404 JSON; wrong method → 405 JSON; bad/missing
  JSON body or missing `url` string → 400 `{error:"bad_url"}`. Each fetcher error code maps to
  the I16 status above. Request aborts (client disconnect, `req.signal`) abort the fetch. Uses a
  15 s fetch timeout (the fetcher's default). Set `idleTimeout` so a 15 s fetch is not cut off.
- Service tests (bun:test) start the server on an ephemeral port and exercise it over real HTTP:
  health 200; a 400 bad_url for `ftp://example.com/` and for a missing url; a 400
  blocked_destination for `http://127.0.0.1:7789/` and `http://[::1]/`; and a 200 success path
  — for the success path the service's app/handler factory may accept an injected fetcher (or
  fetch options) so tests can serve a page from a loopback test server, but `src/index.ts` must
  wire the strict default with no override. Also a 504 timeout and 415 path via the injected
  test fetcher/loopback server.
- Add a `start` script (`bun run src/index.ts`). Add dependencies `defuddle` and `linkedom` with
  `bun add`. If Defuddle's markdown output needs a specific entry (e.g. `defuddle/node`, option
  `markdown: true`), use it; if Defuddle cannot run under Bun+linkedom, return BLOCKED with the
  exact error rather than substituting another library (that is an architecture technology
  choice).
- `cd search && bun test && bun run typecheck` exit 0, and all M6-T1 tests still pass.
