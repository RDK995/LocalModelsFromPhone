Goal:
A pure, dependency-free module `mobile/src/ui/markdown.ts` that turns an assistant reply's markdown into a small block/inline tree the phone can render, never throws on any input (including a half-streamed prefix), and a `visibleText` helper that returns exactly the text a reader would see — so tests and the live proof can assert no raw markdown characters are visible.

Relevant Requirements:
- FR26 (.harness/requirements.md lines 125-129): every assistant answer renders its markdown (bold, italics, headings, ordered/unordered lists, inline code/code blocks, links) instead of raw markup (`**`, `#`, `[text](url)`); rendering works while streaming (incomplete markup never breaks the view).
- AC20 (lines 193-195): bold, a heading, a list, inline code and a link render with no raw markdown characters visible; a reply mid-stream with unterminated markup renders without error.
- Edge case (line ~271): half-written markup such as an open `**` or `[text](` is shown without error and re-rendered as more text arrives.
- Constraint: pure JavaScript, Expo Go compatible. DO NOT add any dependency — hand-write the parser.

Acceptance Criteria:
1. `mobile/src/ui/markdown.ts` exports exactly these types and functions (names are load-bearing; later tasks import them):
   ```ts
   export type Inline =
     | { type: "text"; text: string }
     | { type: "bold"; children: Inline[] }
     | { type: "italic"; children: Inline[] }
     | { type: "code"; text: string }
     | { type: "link"; url: string; children: Inline[] };
   export interface ListItem { depth: number; children: Inline[] }
   export type Block =
     | { type: "paragraph"; children: Inline[] }
     | { type: "heading"; level: 1 | 2 | 3 | 4 | 5 | 6; children: Inline[] }
     | { type: "list"; ordered: boolean; start: number; items: ListItem[] }
     | { type: "codeBlock"; language: string | null; text: string }
     | { type: "quote"; children: Inline[] }
     | { type: "table"; rows: Inline[][][] }
     | { type: "rule" };
   export function parseMarkdown(source: string): Block[];
   export function parseInline(source: string): Inline[];
   export function visibleText(blocks: Block[]): string;
   ```
2. Blocks: ATX headings `#`..`######` followed by a space (a `#` with no following space, e.g. `#hashtag`, stays text; trailing `#`s stripped); paragraphs (consecutive non-blank lines joined with "\n"); unordered list items `-`, `*`, `+` + space; ordered `1.` or `1)` + space (start = first number); `depth` = leading-indent level (0 for none, +1 per 2+ spaces or tab of indentation, capped reasonably); consecutive items of the same ordered-ness form one list; fenced code blocks with ``` or ~~~ (optional language after the fence; content verbatim, no inline parsing); an UNCLOSED fence at end of input is a codeBlock containing everything after it; `>` quote lines (marker stripped); `---`/`***`/`___` alone on a line → rule (but `---` directly under a paragraph line is still just a rule, no setext headings needed); GitHub pipe tables: a header row plus `|---|` separator row → table (separator row dropped, cells trimmed, leading/trailing pipes optional; cells inline-parsed). A table header row whose separator has not arrived yet (streaming) may render as a paragraph.
3. Inline: `**x**` and `__x__` → bold; `*x*` and `_x_` → italic; `***x***` → bold containing italic (or vice versa); `` `x` `` → code (content verbatim, no nested parsing; double-backtick spans ``` `` a`b `` ``` supported); `[text](url)` → link with inline-parsed children; `<https://...>` autolink → link; backslash escapes (`\*`, `\_`, `` \` ``, `\#`, `\[`, `\]`, `\\`) → the literal character. Emphasis rules that avoid false positives: an opener must be followed by a non-space character; `_` inside a word (snake_case_name) is literal; a lone `*` surrounded by spaces (`5 * 3`) is literal; `[1]` with no following `(` is literal text.
4. Streaming tolerance — an unterminated construct AT THE END OF INPUT hides its markers instead of showing them: an unclosed `**`/`__`/`*`/`_`/`***` opener whose remaining text runs to the end renders that text as bold/italic without the markers (a marker with nothing after it at all, e.g. input ending in `**` or `*`, renders nothing for the marker); an unclosed `` ` `` renders the rest as code; `[text` (no `]` yet) renders `text`; `[text](partial-url` renders a link whose children are `text`. An unclosed opener that is NOT at the end of input (a closer can never arrive, e.g. a stray `**` mid-sentence followed by more text on later lines) — use the end-of-input rule only for the final paragraph/block; elsewhere an unmatched marker stays literal text. `parseMarkdown` NEVER throws for any string (including "", "\n", lone markers, and every prefix of every test fixture).
5. `visibleText(blocks)`: the text a reader sees — blocks joined by "\n"; headings/paragraphs/quotes → their inline text; list items → "• " (unordered) or "<n>. " (ordered, numbered from start) + text, one per line, with two spaces per depth level before the bullet; codeBlock → its text; table → cells joined with "  " (two spaces) and rows with "\n" (so no pipe is visible); rule → "" ; inline: text/code text verbatim, bold/italic/link → their children's text (a link shows only its text, never its URL).
