TASK M12-T1 — search service: a client that drops its request ends the search helper or page fetch

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION, detail: cross-process abort test (HTTP client disconnect -> Bun req.signal -> helper process group kill / upstream fetch abort); may expose a real gap needing a fix.

Goal:
Prove, through the search service's real HTTP entry point, that when the caller aborts an in-flight request the work on the Mac stops: for POST /v1/search the helper process (and its process group) is killed; for POST /v1/read the upstream page fetch is aborted. If either does not happen, fix it in the search service so it does (Red -> Green).

Relevant Requirements:
FR23 ("Stop cancels any in-flight search or page read"), AC17 ("Stop during a search ends it on the Mac"). Milestone M12-AC1 (in .harness/milestones.md): "Stop during an in-flight search or page read ends it on the Mac (search helper process killed or page fetch aborted in the search service) and the reply stops." Architecture .harness/architecture.md C13 (search service, search/), C14 (helper, search/helper/).

Acceptance Criteria:
- A test starts the search service HTTP server in-process (the way search/src/http/server.test.ts already does) with a helper command that is a slow fake (e.g. a script that records its own pid, and a child pid, to a temp file then sleeps far longer than the test), sends POST /v1/search with an AbortController, waits until the helper has started, aborts the client request, and asserts within a bounded time (e.g. <= 3 s) that the helper process AND its child are no longer alive (process.kill(pid, 0) throws ESRCH). It must not pass merely because of the helper time limit: set the helper time limit well above the assertion window.
- A test sends POST /v1/read for a URL served by a slow upstream that sends headers and then trickles/holds the body (use whatever existing seam fetchPage.test.ts / server.test.ts use to allow a local test upstream past the SSRF guard — do not weaken the SSRF guard for production), aborts the client request mid-body, and asserts the upstream observes its connection closed / request aborted within a bounded time, well inside the page-read timeout.
- Both tests fail on a version where req.signal is not propagated (show RED by temporarily disconnecting the signal locally, or by the test failing on baseline if there is a real gap; record which in your return) and pass after.
- Existing search tests pass unchanged; none edited or weakened.
