TASK M22-T2 — The search service never keeps an unreadable page in its 24-hour page memory

Routing: tier Cheap, model haiku, reason_code BOUNDED_LOW_RISK — one condition in one handler, using the
shared check from M22-T1, settled by HTTP-level tests that count page fetches.

Depends on: M22-T1 accepted (`shared/readability.ts` exists).

Goal:
In the search service (C13), a page read whose extracted title+markdown is classed unreadable by
`classifyPage` from `shared/readability.ts` is returned to the caller exactly as today but is NOT stored
in the page cache, so a repeat read of the same URL fetches it again. Readable pages are cached as before.

Relevant Requirements:
- FR47(c) (.harness/requirements.md lines 400-414), FR39 (page cache; see archived M20 for its design).
- Architecture: C13 (.harness/architecture.md lines 175-183); D-M20-1 (line 618 onwards).

Acceptance Criteria (verbatim):
- M22-AC4: "Tests through the search service's page-read API (or POST /v1/chat end to end): a page
  classed unreadable is not stored in FR39's 24-hour page cache, and a repeat read of the same URL
  fetches it again rather than serving it from the cache; readable pages are still cached as before."

Design decisions already taken (do not reopen):
- search/tsconfig.json gains `"@shared/*": ["../shared/*"]` under `paths` (as server/tsconfig.json has).
  Import `classifyPage` from `@shared/readability`; if Bun's runtime does not resolve the alias in
  search/, a relative import `../../../shared/readability` is acceptable — say which in the return.
- In search/src/http/server.ts `/v1/read` handler (around lines 176-196): after `extractPage`, call
  `classifyPage({ title: extracted.title ?? "", text: extracted.markdown ?? "" })` with the default
  minimum; only when readable call `pageCache.set(...)`. The response body/status are unchanged
  (`x-cache: miss` on every read of an unreadable page). The requested->final URL map may still be set.
- No response field is added.

Tests required (new file search/src/http/unreadableCache.test.ts, same patterns as
search/src/http/cache.test.ts — loopback page server that counts requests):
1. A "Client Challenge" page read twice within 24 h -> page server contacted twice; both `x-cache: miss`.
2. A 10-word page read twice -> contacted twice.
3. A readable 200-word article read twice -> contacted once; second `x-cache: hit`.
