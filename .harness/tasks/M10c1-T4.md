Goal:
The server's `GET /v1/icon` accepts a single-label DNS hostname such as `localhost` and forwards it to the search service, so a local host is refused by the search service's guard and the server answers `404 {"error":"no_icon"}` — as M10c1-AC1 requires ("a host that is ... a local ... address is refused and returns no_icon").

Why (defect found by the live proof, .harness/evidence/M10c1-T3-proof.log): `isValidIconHost` in server/src/http/server.ts requires at least one dot, so `host=localhost` returns `400 bad_host` and never reaches the guard. That dot rule came from an over-strict orchestrator packet (M10c1-T2), not from the design. The agreed design (architecture D-M10c-2, C4 bullet) says only: "C4 validates the host is a DNS hostname (no scheme, path, port or IP literal) and delegates to C12". `localhost` is a DNS hostname.
