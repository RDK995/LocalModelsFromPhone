Goal:
The phone-facing server (C4, `server/`) exposes `GET /v1/icon?host=<hostname>` behind the existing bearer-token check, validates the host, and delegates to a new C12 client method `icon(host, signal)` that calls the search service's `GET /v1/icon?host=` (C13, being built in parallel by another task; contract below).

Relevant Requirements:
- FR27 (.harness/requirements.md lines 130-144): the phone asks the FR12 server (token-authenticated) for a site's logo; the Mac fetches it.
- Architecture deviation D-M10c-2 (.harness/architecture.md, heading `### D-M10c-2`), agreed design — follow exactly:
  - **C4 (I4)** gains `GET /v1/icon?host=<hostname>` (bearer auth like every route) -> `200` image bytes with the upstream image `Content-Type` and a `Cache-Control` max-age, or `404 {error:"no_icon"}` when the site has none, refuses, or is blocked; `400 bad_host` for a malformed host; `502`/`504` pass through as `icon_unavailable`. C4 validates the host is a DNS hostname (no scheme, path, port or IP literal) and delegates to C12.
  - **C12 (I15)** gains `icon(host, signal) -> {bytes, contentType} | null`, a thin client of C13.
- C13 contract (what C12 calls, default base http://127.0.0.1:7790): `GET /v1/icon?host=<hostname>` -> `200` image bytes with `content-type` image/* | `404 {"error":"no_icon"}` | `400 {"error":"blocked_destination"}` or `400 {"error":"bad_url"}` | `504 {"error":"timeout"}`; network errors possible if the service is down.

Acceptance Criteria:
1. C12: `server/src/web/tools.ts` `createWebTools(...)` result gains `icon(host: string, signal: AbortSignal): Promise<IconResult>` where the result distinguishes: `{ bytes: Uint8Array, contentType: string }` on 200 with an image/* content type; `null` for C13 404 no_icon or 400 blocked_destination/bad_url (the site refuses/is blocked -> "no icon"); and an "unavailable" outcome for 5xx/timeout/network error so C4 can answer 502/504 `icon_unavailable`. (The design's signature is `{bytes, contentType} | null`; a discriminated result or throwing a typed error for unavailable is acceptable — keep it minimal, document it.) Uses the same baseUrl/fetch/timeout options as the existing client (a 15 s timeout for icon requests is fine). Host is URL-encoded in the query.
2. C4: `server/src/http/server.ts` route `GET /v1/icon` added to the existing route table, authenticated like every other route (401 without/with wrong token — auth already runs before routing; confirm with a test). Responses: 200 bytes with upstream content-type and `Cache-Control: private, max-age=86400`; 404 `{"error":"no_icon"}`; 502 or 504 `{"error":"icon_unavailable"}` (504 on timeout, 502 otherwise).
