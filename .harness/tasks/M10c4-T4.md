Design (follow it; it is the interface the app task depends on):
1. shared/api.ts: SourcesEvent items become `Array<{ title: string; url: string; n?: number }>`.
   `n` present only for a page read with read_page in this reply. Search-only items have no `n`.
2. server/src/web/tools.ts:
   - `execute(call, signal, numberPage?: (finalUrl: string) => number)`. On a successful read_page,
     readPage calls `numberPage(finalUrl)` (when given) and the tool result's first line is
     `Page [n]` followed by the existing `Title:` / `URL:` lines (e.g. "Page [2] - cite this page as [2]").
     The literal `[n]` must appear in the text given to the model. A failed read gets no number and does
     not call numberPage.
   - The `source` WebEvent for a successful read carries `n` (search `source` events carry none).
   - Search listing stays free of bracketed numbers (the existing `1.` style is fine; do not introduce `[1]`).
   - systemNote: replace the markdown-link citation sentences (everything from "Cite the pages you relied
     on." up to and including "Only link pages that those tools returned.") with cite-by-number guidance:
     cite each page relied on by its page number in square brackets, e.g. [2], including source cells
     inside tables; cite only numbers given by read_page; do not type URLs as citations. You MAY reuse
     the process wording from .harness/evidence/M10c4-T3-attempt4.patch (it made the model do at least two
     web_search calls with different wording and read_page on results from at least three different
     websites, raising pages read to 8-10) but NOT any of its URL-copying / "never [1]" / "never 【】" /
     link-format wording, which now contradicts FR31. Keep it concise; keep the 10-call cap in mind.
     Keep the date sentence and the "narrow factual question need not search more than it needs" sentence.
3. server/src/generations/manager.ts (the web loop around lines 140-265):
   - Per generation, keep a map from a normalized URL key to page number; `numberPage(finalUrl)` returns the
     existing number or assigns the next one (1, 2, 3 ... in first-read order).
   - URL key = FR27 comparison: ignore scheme http/https, a leading `www.` on the host, and a trailing slash.
     Implement a small pure helper in server (e.g. server/src/web/pageNumbers.ts) with its own tests.
   - When a `source` event with `n` arrives: if a saved source with the same URL already exists (e.g. it was
     first a search result), set its `n`; otherwise push `{ title, url, n }`. Existing de-duplication by url
     is otherwise unchanged. The final `sources` event therefore carries each read page's number.
   - No other behaviour change: no check, rewrite or re-prompt of the model's text or choices; the
     MAX_TOOL_CALLS cap and its tests unchanged.
