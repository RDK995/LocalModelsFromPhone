TASK M3-T2 — Conversations on the phone: list/create/open/delete screen, chat bound to a stored conversation with full history on every send, per-reply model label, and a "load a model" prompt when nothing is resident

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION
  detail: wires an existing store (M3-T1) and existing send controller into expo-router screens plus one pure session module; ordinary UI/state implementation with a unit-test oracle for the logic.

Goal:
The app opens to a list of conversations (newest first). The user can start a new one, open one,
or delete one. Inside a conversation, every prompt is sent with all of that conversation's
earlier turns; each assistant reply is saved with, and shows, the name of the model that produced
it (so after the user switches model mid-conversation, older replies keep their old label and new
ones show the new model). All of it is saved through the M3-T1 store, so it is still there after
the app is force-quit and reopened. If no model is loaded, sending is blocked and the screen says
so and offers a way to the Models screen to load one.
