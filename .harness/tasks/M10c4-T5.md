Goal:
In the phone app, show a citation mark `[n]` (and the grouped / 【n】 forms) in an answer as the logo of
the reply's saved source numbered n, tapping it opening that source's exact saved URL, per FR31.

Relevant Requirements (read them in full):
.harness/requirements.md FR31 (line ~178), FR27 (line ~137), AC25, the edge cases about numbered
citations (lines ~354-364), and the Decisions entries "Cite by number..." and the FR31 defaults.

Interface already in place (from task M10c4-T4, committed): shared/api.ts SourcesEvent items are
`{ title: string; url: string; n?: number }`; `n` is present only for pages the model read, numbered
1, 2, 3 ... per reply. The server's final `sources` event carries them.

Acceptance Criteria:
- M10c4-AC4: Unit tests (app): [n], [1][3], [1, 3] and 【n】 marks render as page n's logo (FR27 logo and
  fallback rules) opening its exact saved URL, with the mark not shown; an unknown number, a mark in a
  reply without numbered sources (a reply saved before this change), and a mark inside inline code or a
  code block stay plain text; a half-streamed [2 renders without error; a reopened saved reply resolves
  the same logos as the live one; FR27 link logos are unchanged.

Design:
1. mobile/src/api/client.ts (sources case ~line 990): keep `n` on an item when it is a positive integer;
   otherwise omit it. Check mobile/src/store/conversationStore.ts and mobile/src/ui/streamReducer.ts keep
   `n` through save/reopen/resume (they must not strip it); fix if they do.
2. mobile/src/ui/sourceLinks.ts: `LinkSource` gains `n?: number`; add a pure `sourceByNumber(n, sources)`
   returning the source whose `n` equals n, else null (null when no source has any `n`).
3. mobile/src/ui/markdown.ts inline parser: a new inline node, e.g.
   `{ type: "cite"; numbers: number[]; raw: string }`, for:
   - `[n]` (digits only), a run of adjacent marks `[1][3]` (one node per mark or one grouped node - your
     choice), `[1, 3]` / `[1,3]` (comma-separated digits),
   - `【n】` and `【n` followed by any extra text `】` (e.g. `【2†L1-L4】`, `【3†source】`) - the number is
     the leading digits.
   Must NOT take: a markdown link `[2](url)` (stays a link), anything inside inline code or a code block
   (the parser's existing code handling must win), an unclosed `[2` (stays text, no error). `raw` is the
   original mark text. visibleText/inlineText treat a cite as its raw text (unchanged selection/copy
   behaviour is fine).
4. mobile/src/ui/inlineLink.ts: a pure `presentCitation(n, sources)` returning the same LinkPresentation
   shape as presentLink: `{ kind: "source", url: <exact saved url>, host }` when resolved with a usable
   host, else `{ kind: "plain" }`.
5. mobile/src/ui/MarkdownText.tsx: render each resolved number as the existing SourceLogo (same props as
   the FR27 link case: same logo, globe fallback and onOpenSource(url) tap), with the mark text not
   shown. Any number that does not resolve renders the original raw text as plain text (for a grouped
   mark, resolve each number; if ANY number in a group does not resolve, render the whole raw mark as
   plain text - simplest and still correct per FR31). The existing link case is unchanged.
