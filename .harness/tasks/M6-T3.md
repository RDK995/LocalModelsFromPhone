Acceptance Criteria (verbatim from .harness/milestones.md, M6):
- M6-AC1: POST /v1/read on the search service (127.0.0.1:7790) with a real public article URL
  returns 200 with its main text as markdown (boilerplate removed) and truncated false; a page
  longer than the size limit comes back truncated true with a truncation marker.
- M6-AC2: POST /v1/read refuses with 400 blocked_destination each of http://127.0.0.1:7789,
  http://localhost, a 100.x tailnet address, a 192.168.x.x address, http://[::1], and a
  hostname that resolves to 127.0.0.1; the check is made on the address actually connected to
  (no DNS-rebinding gap).
- M6-AC3: A public URL that redirects to any blocked destination is refused (every redirect hop
  re-checked), and a non-http(s) scheme returns 400 bad_url.
- M6-AC4: Non-text content returns 415 unsupported_content, and a fetch exceeding its time limit
  returns 504 timeout instead of hanging.

Case guidance (verify each choice works live before relying on it; pick stable targets):
- AC1 normal: a real, stable public article (e.g. a Wikipedia article of moderate size, or a
  well-known blog post) — assert 200, `truncated:false`, markdown contains a distinctive sentence
  from the article body, and does NOT contain an obvious boilerplate string from that page's
  nav/footer (choose one you verified is present in the raw HTML). If a moderate Wikipedia
  article exceeds 40 000 chars pick a shorter page for this case.
- AC1 oversized: a real long public page (e.g. a very long Wikipedia article) → 200,
  `truncated:true`, markdown ends with the truncation marker.
- AC2: http://127.0.0.1:7789, http://localhost, http://100.100.100.100 (and/or the Mac's own
  100.x tailnet IP from `tailscale ip -4` if available), http://192.168.1.1, http://[::1], and a
  public DNS name that resolves to 127.0.0.1 (e.g. `localtest.me` or `127.0.0.1.nip.io`; check
  with `dig +short` first and record the resolution) → each 400 blocked_destination.
  Connect-time evidence: additionally start a throwaway sentinel HTTP listener on 127.0.0.1 (a
  free port) and request `http://127.0.0.1.nip.io:<port>/` (or the localtest.me equivalent);
  assert 400 blocked_destination AND that the sentinel received zero requests.
- AC3: a public redirector to a blocked destination, e.g.
  `https://httpbin.org/redirect-to?url=http://127.0.0.1:7789/` and one to
  `http://100.100.100.100/` (verify httpbin or an equivalent such as
  `https://httpbingo.org/redirect-to?url=...` responds 302 first with curl -I) → 400
  blocked_destination. Non-http scheme: `file:///etc/passwd` and `ftp://example.com/` → 400
  bad_url.
- AC4: non-text: a public PNG/PDF URL (e.g. `https://httpbin.org/image/png`) → 415
  unsupported_content. Timeout: a public URL that delays longer than 15 s (e.g.
  `https://httpbin.org/delay/20` — httpbin caps delay at 10 s, so check; alternatives
  `https://httpbingo.org/delay/20`, or a slow-drip endpoint) → 504 timeout, and assert with
  curl `--max-time 30` that the service answered in under ~20 s (measure and print elapsed).
  If no public endpoint can exceed 15 s, record that and instead show the 504 path via the unit
  test, and say so in Unresolved issues — do not fake it.
