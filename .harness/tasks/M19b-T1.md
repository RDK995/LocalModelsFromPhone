TASK M19b-T1 — One structured log line per deep research model call, and the research num_ctx on load of the deep-research model (FR41)

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION — threads a logger and a
num_ctx through four existing modules (Ollama client, model manager, HTTP server wiring, research
loop) with a clear HTTP-level test oracle; no new concurrency.

Goal:
Every model call a deep research run makes (every attempt of every step) writes exactly one
structured log line with the FR41 fields. When the server loads the configured deep-research model
(POST load through the model manager), the Ollama load request carries `options.num_ctx` equal to the
research `numCtx`, so the first research call does not rebuild the runner. Loads of any other model,
and ordinary (non-research) replies' Ollama chat requests, are byte-for-byte unchanged.

Relevant Requirements:
- FR41 (.harness/requirements.md lines 314-321). Read it in full.
- FR40 (lines 311-313): ordinary replies unchanged.
- Milestone criterion M19b-AC1 (.harness/milestones.md, section "## M19b", lines 425-466).

Acceptance Criteria:
- server/src/generations/research.ts:
  - `modelStep` takes a step name as its first argument. Names, exactly: "brief", "plan",
    "queries" (query proposal), "pages" (page choice), "notes" (note-taking), "gap" (gap check),
    "write". Every existing call site passes its name.
  - `ResearchRunOptions` gains optional `log?: (line: ModelCallLog) => void`. Export
    `type ModelCallLog` and a default logger `logModelCall` that writes
    `console.log(JSON.stringify({ event: "deep_research_model_call", ...line }))` (one line).
  - For every attempt (each iteration of the retry loop that sends a request), exactly one log line
    is written after the attempt ends however it ends (valid, invalid JSON, failed validation,
    stream error, abort/deadline — use try/finally so a thrown abort still logs). Fields:
    `step` (name), `think` (the `think` value actually sent in that request), `attempt` (1-based),
    `wall_ms` (ms from send to end), `load_duration`, `prompt_eval_count`, `prompt_eval_duration`,
    `eval_count`, `eval_duration` (from the final `done` chunk; `null` when no done chunk arrived),
    `thinking_chars` (total characters of `message.thinking` across all chunks, 0 if none),
    `outcome`: one of "ok" | "invalid" | "error" | "aborted".
  - Keep the existing evalCount/evalDurationNs accounting.
- server/src/generations/manager.ts: GenerationManager accepts the logger (e.g. an optional
  constructor parameter or option after `researchSettings`; keep existing call sites compiling)
  and passes it to `runResearch`. Default is `logModelCall`.
- server/src/ollama/client.ts: `OllamaGenerateRequest` gains optional `options?: { num_ctx?: number;
  [k: string]: unknown }`; `load(name, options?)` sends `options` in the /api/generate body only when
  given. `load(name)` with no options sends exactly what it sends today.
- server/src/models/manager.ts: ModelManager learns the deep-research model name and research
  num_ctx (e.g. constructor timing/options object gains `researchModel?: string; researchNumCtx?:
  number`, or a separate optional parameter — keep existing constructions compiling). In `load`,
  when `name === researchModel` it calls `this.ollama.load(name, { num_ctx: researchNumCtx })`;
  otherwise `this.ollama.load(name)` exactly as before. Update the `ModelManagerOllama` interface
  accordingly (second parameter optional).
- server/src/http/server.ts: where it constructs `new ModelManager(ollama, genManager)` (around line
  420), pass `researchModel` and the research num_ctx. The num_ctx must be the same value the
  research run uses: expose from GenerationManager a getter (e.g. `researchNumCtx()`) returning
  `{...DEFAULT_RESEARCH_SETTINGS, ...researchSettings}.numCtx`, and use it here.
- No global Ollama context setting is touched (no OLLAMA_CONTEXT_LENGTH or similar anywhere).
- New test file server/src/http/deepResearchModelCalls.test.ts (bun:test), modelled on the setup
  helper in server/src/http/deepResearch.test.ts (copy what you need; do not import from another
  test file). Through POST /v1/chat with `deep_research: true` and a scripted fake Ollama it proves:
  1. a complete run writes exactly one log line per model request sent (count log lines == count of
     chat requests the fake received), each with every field above, correct `step` names in order,
     `think` equal to the request's `think`, and done-chunk numbers copied (give the fake's done
     chunk distinct non-zero load_duration/prompt_eval_count/prompt_eval_duration/eval_count/
     eval_duration and some `message.thinking` text on one chunk, and assert them);
  2. a step whose first reply is invalid JSON then valid logs attempt 1 outcome "invalid" and
     attempt 2 outcome "ok";
  3. loading the deep-research model through the model-load HTTP route makes the fake's `load` (or
     generate) receive `{ num_ctx: <research numCtx> }`, using a non-default numCtx in the research
     settings to prove it is the same value; loading a different model sends no options;
  4. an ordinary web reply (deep_research false) and a switch-off reply send Ollama chat requests
     with no new fields compared to before (assert no `num_predict`, and `options`/`think` as the
     existing ordinary-reply tests expect), and write no deep_research_model_call log line.
- server/src/ollama/client.test.ts / models/manager.test.ts: add a focused test that `load(name,
  {num_ctx})` sends options in the body and `load(name)` does not.
- All existing tests pass; typecheck passes.
