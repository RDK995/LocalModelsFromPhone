Observed defect (human, on the iPhone, Tailscale ON, Expo Go, after fix cycle 2):
The app opens to the Setup screen. Tapping the token input brings up the on-screen
keyboard, which covers the Continue button. Tapping outside the input does not dismiss
the keyboard. The human could not get past Setup, so Chat and Settings were never reached.

Diagnosis so far (confirm or refute it from the code; do not take it on trust):
- mobile/src/app/setup.tsx: plain <View> with justifyContent "center"; no
  KeyboardAvoidingView, no ScrollView, no Keyboard.dismiss anywhere. The token TextInput
  is `multiline={true}` with minHeight 100, so the Return key inserts a newline instead of
  submitting/closing the keyboard, and there is no onSubmitEditing. iOS also ignores
  `secureTextEntry` on a multiline input.
- mobile/src/app/settings.tsx: the same multiline token TextInput with Save/Cancel below
  it, same lack of keyboard handling.
- mobile/src/app/chat.tsx: the message TextInput and Send/Stop buttons sit in an input
  bar at the bottom of a SafeAreaView with no KeyboardAvoidingView, so the keyboard will
  cover the input bar and Send/Stop. The Stack header is also shown above chat's own
  in-screen header (mobile/src/app/_layout.tsx), which matters for any keyboard offset.

Goal:
On each of Setup, Settings and Chat, on an iPhone: while the keyboard is up, the screen's
action button(s) (Continue; Save and Cancel; Send and Stop) and the input being typed in
stay visible above the keyboard and are tappable; tapping outside the input (and, for
single-line token fields, the keyboard's Return/Done key) dismisses the keyboard.
