TASK M19-T1 — Two-stage Stop for a deep research run (first Stop: short `partial` report; second Stop: stopped, no report)

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION — cancellation-signal
composition inside the existing research module and generation manager with a clear HTTP-level test
oracle; the run-owned signal structure already exists (D-M17-1), this adds one more stage to it.

Goal:
For a deep research run, the first Stop (POST /v1/generations/{id}/cancel) cancels every in-flight
search, page read and model request of the research phase at once and moves the run to writing a
short report from the notes gathered so far under its own short time limit (setting, default 60000
ms), ending with `done.research.status: "partial"`. A second Stop during that write-up cancels it and
the reply ends stopped (`done.status: "cancelled"`) with the steps and sources already streamed but
no report content. Ordinary (non-research) replies keep their one-stage Stop unchanged.

Acceptance Criteria:
- server/src/generations/research.ts: `runResearch` accepts an optional second signal (e.g.
  `stopSignal`, "wrap up") in addition to the existing hard `signal`. `ResearchSettings` gains
  `stopWriteMs` (default 60000 in DEFAULT_RESEARCH_SETTINGS; the short write-up limit after a first
  Stop).
  - stopSignal aborted during planning/searching/reading: the research-phase signal (which every
    search, read and model call of the phase already receives) aborts immediately, so in-flight
    calls are cancelled at once; the run moves to the write phase exactly like the research deadline
    does, but the write-up's signal also aborts `stopWriteMs` after the Stop (and never later than the
    existing final budget deadline). The run ends with `done.status: "complete"` and
    `research.status: "partial"` (the report from the notes so far, cited/cleaned exactly as today).
    If there are no notes yet, no write call is made and the existing no-report/gathered-notes text is
    used, still `partial`.
  - stopSignal aborted while the normal write-up is already running: the write-up's remaining time
    is capped at `stopWriteMs` from the Stop; the run ends `partial`.
  - The hard `signal` aborted at any point (including during the short write-up): unchanged
    behaviour — `done {status:"cancelled"}`, no `content` event for the report. Steps already
    emitted stay in the log. Additionally, emit the `sources` event (pages read so far) before the
    cancelled `done` if any search ran, so a stopped run keeps its sources (check the current code: if
    a stopped run already keeps its sources by another route, leave it).
- server/src/generations/manager.ts: a deep research generation record carries a second controller
  for the first Stop. `cancelGeneration(genId)` on a running deep research generation: first call
  aborts the stop ("wrap up") controller and returns true; a later call aborts the hard controller
  and returns true. Ordinary/web generations: unchanged (one call, hard abort). `cancelActive()`
  (used by a confirmed model load/unload, FR6) aborts a deep research run hard at once (both
  controllers) so an unload never waits for a write-up.
- POST /v1/generations/{id}/cancel response shape is unchanged (`{status:"cancelled"}` when the call
  was accepted, `already_complete` otherwise) for both stages.
- Tests (write first, see them fail, then implement):
  - server/src/generations/research.test.ts: unit tests with scripted fakes for (a) first Stop during
    a search: the fake search's own signal is aborted within ~50 ms of the Stop; a write step
    follows; done `complete` + research `partial`; (b) first Stop during a page read: same; (c) the
    short write-up is limited by `stopWriteMs` (use a small value, e.g. 200 ms, and a write call that
    never resolves until its signal aborts: run ends `partial` within stopWriteMs + margin, never
    hangs); (d) hard abort during the short write-up: done `cancelled`, no report `content` event,
    steps and `sources` present; (e) first Stop with no notes: no write call, `partial`.
  - A new HTTP-level file server/src/http/deepResearchStop.test.ts, modelled on
    server/src/http/deepResearch.test.ts (createServer + GenerationManager + fake Ollama + fake web
    tools): POST /v1/chat with `deep_research:true`, then POST the cancel route once → the SSE stream
    (GET /v1/generations/{id}/events) ends with a `write` step, one report `content` event and done
    research `partial`; and a second scenario where cancel is POSTed twice (second during the
    write-up) → stream ends `done {status:"cancelled"}`, has the earlier steps and `sources`, and no
    report `content` event.
  - A manager-level test that `cancelActive()` on a deep research run ends it `cancelled` promptly.
- Existing tests keep passing unchanged.
