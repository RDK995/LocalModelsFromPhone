Design (decided — follow it):
1. server/src/web/tools.ts: extract an exported pure function `todayLine(now: Date): string` that returns exactly the first sentence systemNote produces today, e.g. `Today's date is Saturday, October 3, 2026 (2026-10-03). ` minus the trailing space — i.e. "Today's date is <Weekday>, <Month> <d>, <yyyy> (<yyyy-mm-dd>)." Make systemNote use it so systemNote's output is byte-for-byte unchanged (existing tools tests must pass unmodified).

In modelStep the user message becomes `${userContent}\n\n${todayLine(now())}\n\nTask: ${task}` — step content (page text for notes) stays FIRST and the task stays LAST, as FR43 requires; the date line sits between them. (Revised after attempt 1: putting the date first broke FR43's "page text first" rule and the existing deepResearchPassages.test.ts assertions.) SYSTEM_INSTRUCTIONS is NOT changed. Do not put any date anywhere in the system message.
3. server/src/generations/manager.ts: add an optional 5th constructor parameter `now: () => Date = () => new Date()`, stored as a field; pass it to runResearch as `now`. Also use `this.now()` in place of `new Date()` for the ordinary web systemNote (behaviour unchanged). Do not change the order or defaults of existing params; server/src/index.ts and server/src/http/server.ts need no change (they rely on defaults).
4. New test file server/src/http/deepResearchDate.test.ts, modelled on server/src/http/deepResearchModelCalls.test.ts (copy its fake-Ollama / createServer / SSE helpers): build `new GenerationManager(fakeOllama, fakeWebTools, settings, () => {}, () => fixedDate)`, POST /v1/chat with web:true, deep_research:true, record every request the fake Ollama receives. Assert:
   a. every request's user message contains `todayLine(fixedDate)` and the literal expected string for a hard-coded date (e.g. for new Date(2026, 9, 3, 12) -> "Today's date is Saturday, October 3, 2026 (2026-10-03).") — assert the literal too, so the format is pinned, not just self-consistent;
   b. no request's system message contains "Today's date" or the ISO date;

   d. the system message is identical across all requests in a run, and identical between a run on 2026-10-03 and a second run on a different day (e.g. new Date(2026, 11, 25, 12) -> "Friday, December 25, 2026 (2026-12-25)") whose user messages carry the second date.
   Use local-time Date constructors (as tools.ts uses getDate/getDay), not UTC strings.
