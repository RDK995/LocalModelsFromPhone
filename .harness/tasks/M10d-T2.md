Goal:
A Mac-side live proof, `mobile/scripts/sources-list-proof.sh` (wrapper) + `mobile/scripts/sources-list-proof.ts`
(assertions), that runs a real web-on chat through the server's POST /v1/chat, takes the reply's saved
`sources` event, and proves through the phone app's own modules (mobile/src/ui/sourceListModel.ts from task
M10d-T1, the client's sources parsing, the icon cache / GET /v1/icon) that the Sources list for that reply
starts collapsed with header "Sources (n)" where n equals the number of saved sources, toggles open and
closed, and when open yields exactly n separate entries, one per saved source, each with its own saved URL
and a title, and each entry's host gets a logo from the Mac (image) or the globe fallback - never a
merged entry. Then run it once and keep the log.

.harness/requirements.md FR28 (lines 152-156), FR27 (logo rules), AC22 (lines 251-254).

  collapse on tap, and each source is its own tappable entry (logo + title) opening in Safari - including a
  source set shaped like the 2026-09-30 phone screenshot in which several sources rendered glued into one link.

Checks the proof must print as PASS/FAIL (exit non-zero if any FAIL):
1. Resident Ollama model unchanged before/after.
2. One broad web prompt (e.g. "What are today's top technology news stories? Cite your sources.") returns a
   reply with >= 3 saved sources; record the model name, prompt, source count and the sources list (title,
   url, n) in the log and in .harness/evidence/M10d-T2-replies.json. If a reply comes back with fewer than
   3 sources, retry with a second broad prompt once before failing.
3. View-model over those live sources: header text is exactly `Sources (<count>)`; initial state collapsed;
   toggle -> expanded; toggle again -> collapsed.
4. Entries: count equals the source count; keys distinct; entry i url === saved source i url; every title
   non-empty and single-line; no entry's title contains another entry's url.
5. Logos: for each distinct entry host, the icon cache (through the real Mac /v1/icon) yields image or
   null -> globe; print host -> image|globe. This check passes as long as every entry has a logo display
   (image or globe) and the network observation shows only SERVER/v1/icon requests (as source-logo-proof).
6. Screenshot-shaped fixture (offline, same assertions as 4): 6 sources including two on the same site
   (www.wsj.com and wsj.com), one empty title, one title with a newline, one very long URL, two with the
   identical URL -> 6 separate entries, same host for the shared-site pair.
7. Bundle freshness (lesson from M10c3, where the phone ran stale code): the wrapper restarts the
   com.harness.bundle-host LaunchAgent (launchctl kickstart -k gui/$(id -u)/com.harness.bundle-host) so the
   phone downloads the new code, and prints the time it did so.

Wrapper writes full output to .harness/evidence/M10d-T2-proof.log. Add a `--self-test` mode running only
the offline checks (3-4 on a fixed fixture and 6) with no server, no model, no network, exit 0 on pass.
