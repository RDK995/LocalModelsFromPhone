TASK M17-C1 — A run with no usable material ends `failed`, never an uncited report labelled `complete`

Routing: tier Mid, model sonnet, reason_code ORDINARY_IMPLEMENTATION — a bounded change to the
end-of-run status rule in one function plus tests; the deadline/signal design from M17-T1 is not

Goal:
In `runResearch` (server/src/generations/research.ts), a run whose searches were attempted but which
gathered no usable material — no note survived (no page read, or pages read but none produced a
note) — ends with research status `failed` and a plain sentence as its answer, skipping the write
model call, instead of asking the model to write from "(none yet)" notes and labelling it `complete`.

Relevant Requirements:
- FR36 (.harness/requirements.md lines 267-277): `complete` = finished normally; `partial` = stopped
  early by the deadline or Stop, or with gaps; `failed` = no usable material (e.g. every search
  backend unavailable), answer is a plain sentence, plus any steps. Never an error and no reply.

Decision already taken (follow it; do not redesign):
1. New rule at research.ts ~line 535 (the `const failed = ...` line):
   failed = searchesRun > 0 && notes.length === 0
   (today it is `searchesRun > 0 && searchesWithResults === 0 && readNumbers.size === 0`; the new rule
   is a superset of the old one, so every run that was `failed` before stays `failed`).
2. Answer sentence when failed:
   - searchesWithResults === 0 → `COULD_NOT_SEARCH_NOTE` exactly as today (unchanged text).
   - otherwise → a new exported constant `COULD_NOT_READ_NOTE`, placed next to
     `COULD_NOT_SEARCH_NOTE` with a one-line doc comment, text exactly:
     "The research found search results but could not get anything usable from the pages — none could be read or none had relevant content. Try again later."
3. When failed, the write model call is skipped and no `write` step is emitted (same as today's
   failed path). The `content` event carries the sentence; the `sources` event is still emitted when
   searchesRun > 0 (as today); `done.status` stays "complete" and `done.research.status` is "failed"
   with elapsed_ms/budget_ms as today.
4. A user Stop (cancelled) and everything else in the run is unchanged.
