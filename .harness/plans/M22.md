# M22 — Bot-check and near-empty pages are never listed as sources, and deep research reads another page in their place — task plan

Status: AGREED
## Summary

Some web pages are not real pages: they are "prove you are not a robot" screens (like the two
scribd.com "Client Challenge" pages in your M21 phone run) or are almost empty. After this milestone
those pages never get a number and never appear under "Sources". In deep research, the Mac reads the
next search result instead, as long as time allows, without running a new search. In an ordinary web
reply, the model is told plainly "that page could not be read (bot check / almost no text)" so it can
pick another one. The search service also stops remembering such pages for 24 hours, so a second try
fetches the page fresh. You will see it working through tests that drive the real chat address
(POST /v1/chat) with a fake search service and a fake model; the live proof on the Mac with your World
War Two question is M24.

**Where the one check lives, and why.** The rule "is this page readable?" is needed in two programs: the
search service (to decide whether to keep the page in its 24-hour memory) and the chat server (to decide
whether the page gets a number). The plan puts the rule once in the project's existing `shared/` folder,
which both programs can already use (today it holds the message formats the phone and server share). So
there is one copy of the rule, both programs run that same copy, and they can never disagree. The
alternative was to have only the search service judge pages and tell the server; that works until the
search service is running older code, at which point the server would silently start listing robot
pages again. It would also leave M24 with no simple way to re-check saved pages.

## Risks and open points

- **Existing tests change on purpose.** One existing test (deep research "empty, blocked and irrelevant
  pages ... numbering is unchanged") checks the old rule, where robot pages still got a number. FR47
  reverses that rule, so that one test's expectations are updated to the new rule. Many other tests use
  tiny sample pages (one or two words) that would now count as "almost empty"; those sample texts are
  lengthened, with no checks changed. The verifier will be asked to confirm nothing was loosened.
- **The phone wording.** The phone already shows a failed read as "Reading: scribd.com (failed)". FR47
  says no phone change, so that is what you will see, not the exact words "couldn't be read".
- **Which result replaces a dropped page.** The plan takes the next unread result in the order the
  search returned them, with no extra model call to choose. Simple and predictable; it could pick a
  slightly less relevant page than a fresh model choice would.
- **The 40-word line is fixed, not a setting.** Both programs use FR43's 40 words from the shared rule.
  Deep research's own note setting stays as it is for its later checks.
- **The robot-check word list is a best guess.** "Client Challenge" is added. A robot screen using
  wording not on the list still gets through, as today.
- **Small design note to record.** Putting logic (not just message formats) in `shared/` will be written
  down as a non-material change in `.harness/architecture.md` during implementation; no program's job
  changes.
- **For M24.** M24's re-check of saved pages will use `classifyPage` from `shared/readability.ts`. The
  live proof also needs the always-on search service restarted onto this code, not only the chat server;
  M24's ask to you should cover both.
- **Small thing noticed, not in scope.** Readable pages with no useful passage are logged as "empty"
  rather than the "no-match" wording the requirements use. Left as a follow-up.
