## Risks and open points

- **You are needed twice.** After the four runs, you read the reports (about 10-15 minutes) and say what
  you think — that is recorded but does not pass or fail anything. Separately, you run one deep research
  question on the phone and send the screenshot. Please don't start a deep research reply on the phone
  while the four Mac runs are going (about 15-35 minutes): only one can run at a time and yours would
  make a Mac run fail.
- **No restarts planned.** The chat server's code has not changed since it was last restarted, and M20
  already restarted the search service. If the first check finds either running old code, or the model
  not loaded, the plan stops and asks you rather than restarting or loading anything.
- **A run can fail the bar.** Earlier, one heat-pump run read only 2 pages. M20 changed searching to ask
  one engine at a time and to rest blocked engines, which may help or hurt. A failed run is not quietly
  re-run until it passes: it is recorded, and you are asked whether to re-run it or look into why.
- **Search engines may be resting.** If an engine blocked the Mac recently, M20 rests it for up to a day,
  so runs lean on the remaining engines and the headless browser. That is the designed behaviour, but it
  can mean fewer pages found.
- **Depends on earlier milestones only as built.** Everything this plan uses (the live-run script, the
  question list, the readiness script, M20's search changes) is already built and committed; no task
  rests on another milestone's unbuilt plan.
