# M20 — Search backends rest after being blocked, and repeated searches and page reads come from cache — task plan

Status: AGREED
## Summary

The Mac's search service will remember when a search engine has told it to back off. A "too many requests"
answer rests that engine for an hour; a "prove you are not a robot" page rests it for a day. Meanwhile
searches go to the other engines, then the headless browser. The service will also keep answers for 24
hours, so asking the same search twice, or reading the same page twice, doesn't go back out to the
internet. You'll be able to see it working through the search service's own web address (its tests drive
it with fake engines and a fake clock), and then live: the existing web-chat checks are re-run against the
real, restarted service. A repeated search shows it came from the cache.

## Risks and open points

- **Which engines, and searching one at a time.** The search library today asks several engines at once
  and hides which one failed, so it can't tell who blocked us. The plan asks engines one at a time, in a
  fixed order: DuckDuckGo, Bing, Brave, Mojeek (changeable by a setting). Two side effects: (1) ordinary
  web replies may get slightly different results than today, because Wikipedia is no longer asked first;
  (2) when several engines fail, a search takes longer (each engine gets 4 seconds before the browser is
  tried, still inside the existing 25-second limit).
- **Memory, not disk.** Resting engines and cached answers are kept in the search service's memory. If the
  Mac restarts the service, the cache empties and a rested engine may be tried again early. Simpler and
  easy to test; disk storage could be added later if it matters.
- **Restarting the always-on search service.** M20-T4 restarts `com.harness.search` (the background search
  service on the Mac) so the live proofs use the new code. Agreeing this plan is taken as permission for
  that one restart. The chat server itself is not restarted.
- **The CAPTCHA check is a best guess.** Real engines show "are you a robot" pages in many forms; the
  helper looks for common wording. A form it does not recognise counts as an ordinary failure (not rested),
  which is no worse than today.
- **Interface change, recorded.** The helper's output gains a per-engine list, and the service's responses
  gain an `x-cache` header; both are additive. This will be recorded as a non-material deviation in
  `.harness/architecture.md` (no component boundary or ownership changes — D-M15-1 already put breakers and
  the cache in the search service).
