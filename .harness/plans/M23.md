# M23 — Deep research keeps notes whose quotes differ from the page only trivially, and logs every note it drops — task plan

Status: AGREED
## Summary

During deep research, the model reads a page and writes short notes, each with a quote copied from the
page. Today the Mac throws a note away unless the quote matches the page character for character, so a
curly apostrophe, a long dash, or a link written in the page's formatting is enough to lose it. In your
M21 phone run four pages were read but only one note survived, so the report cited the same page three
times. After this milestone those small differences no longer count: straight and curly quotes are
treated alike, all dashes alike, spacing and capital letters ignored, and link, picture and bold/italic
formatting stripped down to the words you would see. A quote with "…" in it is kept when each piece is on
the page in the right order. A quote whose words are not on the page is still thrown away. Every note
thrown away now leaves one line in the Mac's log saying which run, which page, why, and the start of the
quote, and the end-of-run line gains a count of dropped notes next to the count of kept ones.

You will see it working through tests that drive the real chat address (POST /v1/chat) with a fake
search service and a fake model. The live check on the Mac with your World War Two question is M24.

## Risks and open points

- **One reason in the requirement can never happen.** The requirement lists "invalid page number" as a
  reason a note might be dropped. In this code the Mac, not the model, puts the page number on each note,
  so a note can never arrive with a wrong one. The plan logs the reasons that can happen — no quote, no
  claim, quote not on the page — and does not add a reason that nothing could ever produce. If you would
  rather have it listed anyway, say so; it would be an unused label.
- **The loosened match is slightly looser than the list in one corner.** To keep it simple, bold/italic
  star and underscore marks are removed from both the quote and the page. So a quote and a page that
  differ only by a stray `*` would also match. Underscores inside words (like `max_tokens`) are kept.
- **Notes cut off by the time limit.** When the clock runs out mid-note, the half-written last note is
  not a note and is not logged as dropped; the complete ones before it are checked and logged as usual.
- **Depends on M22, which is planned but not built.** M22 changes the same note-taking code in
  server/src/generations/research.ts (pages that are robot checks or nearly empty are logged and skipped
  before any note is taken, and another page is read in their place). The packets find code by name, not
  line number, and leave M22's changes alone. Those skipped pages are not notes and are not counted as
  dropped. Test pages in M23 are written to be long and readable so M22's rule does not skip them.
- **One existing test changes on purpose.** A test checks the end-of-run log line has an exact list of
  fields. It gains `notes_dropped`, so that one expected list grows by one and the test also checks it is 0. No
  other existing test is changed; if one fails, the worker stops and reports it.
- **For M24.** Drop lines are JSON with `"event":"deep_research_note_dropped"` and fields `run` (the
  generation id), `n`, `reason`, `quote`; the end-of-run line `deep_research_run_end` gains
  `notes_dropped`. M24's live-run script (server/scripts/ac29-live-run.ts) does not read either yet and
  will need a small change to record notes dropped and drop reasons per run; M23 does not touch it.
  M24's restart ask covers the chat server (this code) as well as the search service (M22).
