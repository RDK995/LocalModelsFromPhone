## Summary

M22 stops robot-check and near-empty pages from being listed as sources, and M23 stops good notes being
thrown away over tiny differences like a curly apostrophe. Both are proven only with fake pages and a fake
model. This milestone proves them for real on your Mac: your own question "What was the cause of World
War Two from German perspective" plus the four usual test questions (Raft vs Paxos, home batteries,
WebAssembly, heat pumps) are each run once through the Mac's chat address, one after another, on
`qwen3.5:35b-a3b`. Each run must finish in time with status complete or partial and cite at least three
pages it really read, and none of its listed sources may be a robot-check or near-empty page. For each run
we also write down how many notes were kept, how many were thrown away and why.

How you will see it working: one summary file, `.harness/evidence/M24-T4-summary.md`, with a row per
question (time taken, pages cited, notes kept and dropped, any bad source) and each full report with its
source list. No phone change and no phone screenshot are part of this milestone.

**One question for you before anything restarts.** The live test needs the Mac's two always-on helpers
switched off and on again so they pick up the new code: the chat server, and the search helper that reads
web pages. You have not given standing permission for this round of work, so the run will stop and ask:

> "To test the fixes for real, I need to restart the two background programs on your Mac — the one your
> phone talks to, and the one that fetches web pages. Each restart takes a few seconds. Any reply your
> phone is in the middle of would be cut off, and please don't start a deep research question on the
> phone for the next 30-40 minutes while five test questions run one after another. Is it OK to restart
> both now?"

Your answer is recorded word for word, and nothing restarts until you say yes.

## Risks and open points

- **Depends on M22 and M23, planned but not built.** T1 uses M22's `classifyPage` (shared/readability.ts)
  and M23's `deep_research_note_dropped` line and `notes_dropped` field. If they are built under
  different names, the worker uses what was built and the change is recorded. T2's readiness check also
  confirms M23's last commit is in the running code.
- **"Each saved source's stored text" — where it comes from.** The server keeps only each source's
  title and address after a run, not its text. The one stored copy is the search helper's 24-hour page
  memory, which since M22 keeps only readable pages. So right after each run the script asks the search
  helper for each source again and applies the robot/near-empty rule to what comes back, recording
  whether it came from memory ("hit") or was fetched fresh ("miss"). A hit is the same text the run saw.
  A miss means the page was not in memory, which by itself is a warning sign, and the fresh copy might
  differ from what the run saw; misses are listed in the summary. A source that cannot be re-read at all
  counts as a failure, not a pass.
- **A run that misses the bar is not re-run.** It is written down and brought to you to decide, as the
  requirement says. Real web pages and a real model vary, so one of five missing is possible even if the
  fixes work.
- **Timing.** Each run takes about 3-8 minutes plus up to 90 seconds re-checking its sources, so about
  30-40 minutes in all. The test script stops itself at 10 minutes; a run that hits the limit is recorded
  as a failure, not retried.
- **One run at a time, in the foreground.** The script finds each run's log lines by position in the
  server's log, so a second run — or a deep research question from your phone — during a run would mix
  the logs. Past workers that ran these scripts in the background ran out of turns waiting, and two that
  ran at once overwrote each other's log; the packets forbid both and give every run its own file names.
- **Restarting the search helper clears its memory** of recent searches and pages, and resets its
  "this search engine blocked us, rest it" timers. The first run may therefore search a little slower.
- **Earlier proofs still check.** T1 keeps the script's old behaviour when the new source-text file is
  not given, so M21's recorded checks still pass; T1's test command re-runs them.
